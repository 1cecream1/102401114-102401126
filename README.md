# 校园失物招领（Campus Lost & Found）

---

## 一、项目介绍

一个面向校园场景的**失物招领信息平台**：同学在这里发布「寻物」或「招领」信息，按类型 / 分类 / 地点 / 状态筛选浏览，通过关键词搜索快速定位，并在详情页查看发布者联系方式，形成「**发布信息 → 浏览 / 搜索 → 查看详情 → 联系发布者 → 更新状态**」的完整闭环。在此之上还提供了两项激励功能：**寻物帖可标注悬赏金额**，**招领帖可给拾金不昧的同学打赏**（均为应用内记录，不含真实支付，详见「已知限制」）。

主要功能：

| 入口 | 功能 |
| --- | --- |
| 首页 | 全部 / 寻物 / 招领 三 Tab；分类、地点、状态三个下拉组合筛选；最新发布 / 最近丢失 / 最多浏览 三种排序；数据统计条；信息流卡片（带悬赏 / 打赏徽章） |
| 发布（底部「+」） | 寻物 / 招领双态表单，地点与时间文案随类型自动切换；分类、地点用标签选择；必填项逐项校验并标红；描述实时字数统计；发寻物可**选填悬赏金额**（1~200 元整数）；发布寻物时提示库中已有的同类招领信息 |
| 搜索 | 关键词在**名称 / 分类 / 地点 / 描述**四个字段里做子串匹配（忽略大小写）；热门词一键填入；显示结果条数；无结果时给出空态引导 |
| 详情 | 物品图标与类型标签、地点 / 时间 / 浏览量、详细描述、发布者信息；联系方式**默认打码**，点击后显示并支持一键复制 |
| 详情（招领） | **打赏拾金不昧者**：弹层选固定档位（¥2 / ¥5 / ¥10 / ¥20）或自定义金额，可附一句留言；该帖累计收到的打赏（次数 + 总额 + 明细）实时展示 |
| 我的发布 | 全部 / 进行中 / 已完结 / 收获打赏 四项统计；卡片上直接「标记完结」「撤销完结」「删除」 |

设计与实现上，**逻辑层与页面层分离**：`js/` 下的 7 个模块只负责数据、校验、搜索、打赏与文案，完全不碰 DOM；`js/app.js` 只负责渲染与事件绑定。每个模块都写成「浏览器挂 `window` / Node 用 `module.exports`」的双导出形式，因此同一份逻辑层代码既能被 `index.html` 直接引入，也能被 Mocha 单元测试直接 `require`——测试和线上跑的是同一份代码，不存在「为测试另写一套」的问题。

## 三、使用说明

### 1. 运行

项目是纯静态页面，**不需要安装依赖、不需要启动服务器**：

1. 下载或克隆本仓库到本地；
2. 用 **Google Chrome** 打开根目录下的 `index.html`（双击即可）；
3. 页面自带 **24 条示例数据**，打开后可直接浏览并体验全部功能。

> 页面按移动端（约 375px 宽）布局设计，建议把浏览器窗口调窄，或使用开发者工具的移动端模拟查看。

### 2. 各功能入口

| 想看什么 | 怎么操作 |
| --- | --- |
| 浏览信息 / 筛选 / 排序 | 打开 `index.html` 默认即首页；点顶部「全部 / 寻物 / 招领」切换类型，用下方三个下拉框按分类、地点、状态筛选，点「最新发布 / 最近丢失 / 最多浏览」切换排序 |
| 查看某条信息的详情 | 在首页或搜索结果里**点任意一张卡片**，进入详情页；点「查看联系方式」显示明文，再点「复制联系方式」复制 |
| 发布一条信息 | 点底部导航中间的「**+**」，选「我丢了东西 / 我捡到东西」，填物品名称、分类、地点、时间、联系方式（带 `*` 为必填），点「立即发布」；成功后进入发布成功页，可「查看详情」或「返回首页」 |
| 给物品加悬赏 | 发布时选「**我丢了东西**」，在「悬赏金额（选填）」里填 1~200 的整数（元）；未填即不设悬赏。悬赏会在首页卡片和详情页显示「🎁 悬赏 ¥xx」 |
| 打赏拾金不昧者 | 打开一条**招领**信息的详情页（不是自己发的），点橙色「**🎁 打赏拾金不昧者**」→ 选 ¥2 / ¥5 / ¥10 / ¥20 或自己填金额（1~200 整数）→ 可留一句话 → 「确认打赏」。该帖下方「收到的打赏」会累计显示次数与总额 |
| 搜索物品 | 点首页顶部的搜索框，或从底部导航进入搜索页，输入关键词后点「搜索」或按回车；也可以点「热门：」后面的词直接搜 |
| 管理自己发布的信息 | 点底部导航右侧「**我的**」，可看到自己发布的全部信息；卡片上可「标记为已找到 / 已归还」「撤销完结」「删除」，也可点进详情页操作 |

### 3. 运行单元测试

页面运行**不需要** Node.js；只有想跑单元测试时才需要（需先装好 Node.js）：

```bash
npm install     # 首次运行，安装 mocha 与 chai（联网）
npm test        # 运行全部单元测试
```

预期输出：`181 passing`。测试用 **Mocha + Chai**，用例在 `test/` 目录下，覆盖逻辑层 7 个模块
（`constant` / `seed` / `reward` / `store` / `validate` / `search` / `status`）。测试里 `require` 的就是页面用的那份
`js/` 代码；`store.js` 在 Node 下会把 `localStorage` 自动降级成内存替身，因此不需要 mock DOM、也不需要额外配置。

### 4. 数据说明

- 页面自带 **24 条示例数据**，覆盖全部 8 个分类与 8 个地点，打开就能试所有筛选与排序；其中 3 条寻物帖带悬赏、2 条招领帖带打赏记录，可直接演示这两项功能。
- 数据保存在浏览器本地（`localStorage`）：**刷新、关掉标签页再打开，数据都还在**；发布、完结、打赏、删除的结果同样会保留。
- 换浏览器、换设备或清空浏览器数据后，会重新灌入一套示例数据（不同浏览器的数据互不干扰）。
- 所有信息均为演示用示例数据，不含任何真实个人信息。

### 5. 已知限制与常见问题

本项目是**纯静态页面**（无后端、无账号体系），以下限制是设计选择而非缺陷，在此如实说明：

| 限制 | 说明 |
| --- | --- |
| **打赏不涉及真实支付** | 纯静态页面没有服务端，无法完成真实的资金流转。本项目里的「打赏」是**应用内的打赏记录**：数据真实落在本机 `localStorage`、刷新不丢、可累计统计，但**不会真的转账给对方**，界面上也明确标注了这一点。悬赏金额同理，只是发布者的承诺展示。 |
| **数据不跨设备 / 不跨浏览器** | 数据存在当前浏览器的 `localStorage` 里，换浏览器、换电脑、或清除浏览器数据后都会重新灌入示例数据，彼此互不可见。 |
| **没有账号体系，靠本机标识区分发布者** | 「我的发布」靠首次访问时生成并保存在本机的随机标识判定，所以只能管理**同一台浏览器**上发布的记录；清空浏览器数据后，旧发布不再被认作「我的」。这是静态页面的必然结果，也意味着本应用不采集任何个人信息。 |
| **没有图片上传** | 物品特征靠文字描述 + 分类图标表达，没有引入图片存储（静态页面无处保存文件）。 |
| **「丢失时间」是用户手填的自由文本** | 该字段按原文展示，不参与时间排序。「最近丢失」排序依赖的是发布时记录的**时间戳**，因此对表单里手填的时间仅供参考；发布越晚的记录会被认为越"新丢失"，这一点在示例数据里是精确的、对新发布的数据则是近似。 |
| **没有实时同步** | 没有服务端推送通道，一台设备上的新发布不会自动出现在另一台设备上，需要各自刷新。 |
| **不使用第三方 CDN 或构建工具** | 所有代码与样式都在仓库内，双击 `index.html` 即可运行，不联网也能用。代价是没有打包压缩、也不能引入 npm 运行时依赖。 |
